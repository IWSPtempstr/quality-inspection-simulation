# 可替代规则排程与候选评分的算法路线

本文档记录适合“电器产品质量检测队列仿真系统”的排程算法方向。当前系统仍采用规则排程与候选评分，后续若替换为优化算法，应先把输入约束和验收指标固定下来，再替换 `ScheduleOptimizerService` 或新增求解器适配层。

## 业务抽象

当前问题更接近动态柔性作业车间排程：

- 订单可视为 job。
- 检测步骤可视为 operation。
- 设备实例、人员实例、前处理资源、转运资源和耗材可视为多资源约束。
- `detection_route.sequence` 是工序先后约束。
- `vip/urgent/normal`、承诺完成时间和延期惩罚是目标函数权重。
- 设备故障、维护、人员不可用和检测完成事件会触发动态重排。

## 候选算法

### CP-SAT / 约束规划

适用场景：中小规模订单、约束较多、需要可解释可验证的可行解。Google OR-Tools 官方文档提供了 CP-SAT 和 Job Shop Scheduling 示例，适合把设备互斥、工序顺序、人员容量、维护窗口、耗材容量建模为约束。

优点：约束表达直接；可处理 `NoOverlap`、时间窗、可选区间、累计资源等约束；能给出可行性和目标值。

限制：5000 单全量直接求解可能耗时较高，需要滚动时域、分批或只对受影响区间重排。

参考：

- [OR-Tools CP-SAT guide](https://developers.google.com/optimization/cp/)
- [OR-Tools Job Shop Scheduling](https://developers.google.com/optimization/scheduling/job_shop)
- [OR-Tools Scheduling overview](https://developers.google.com/optimization/scheduling)

### MILP / 混合整数规划

适用场景：需要严格目标函数、延误成本、资源成本和 SLA 违约成本的线性化表达。可用于离线基准实验，验证规则排程与启发式排程的差距。

优点：目标函数表达严谨，适合做小规模最优性对照。

限制：多资源、多工序、动态事件和大规模订单会导致变量数量快速增长；非线性细节需要线性化。

### 元启发式算法

适用场景：中大规模订单，需要较快生成较优解，但不要求证明全局最优。可选遗传算法、禁忌搜索、模拟退火、粒子群、模因算法、变邻域搜索等。

优点：可在较大样本上工作；适合以当前规则排程作为初始解，再做局部搜索改进。

限制：参数敏感，结果稳定性和可解释性需要额外报告；需要设计染色体、邻域操作和修复策略。

### 滚动时域重排

适用场景：订单持续到达、设备故障和人员变动频繁的动态排程。核心思想是只锁定已经开始或即将开始的步骤，对未来窗口内的任务重排。

优点：契合当前事件队列和非抢占式机制；能降低每次重排规模；便于保持运行中步骤不被打断。

限制：窗口大小会影响效果；局部最优可能积累，需要周期性全局复盘。

### 强化学习 / 深度强化学习

适用场景：有大量历史订单、设备状态和人工调度记录后，用于学习派工策略或调度规则选择。更适合作为策略推荐或排序器，而不是第一阶段的唯一排程器。

优点：可适配动态环境；能学习复杂优先级和资源利用模式。

限制：需要大量训练数据、仿真环境和评估基准；解释性、泛化和安全边界需要额外控制。

## 建议替换路径

1. 先保留当前规则排程作为 baseline。
2. 新增 `CpSatScheduleSolver`，只求解未来 1-3 个工作日的窗口，并锁定运行中步骤。
3. 用 500 单数据集做精度验证，用 5000 单数据集做滚动窗口压力验证。
4. 若 CP-SAT 运行时间不可接受，再引入元启发式做大样本近似优化。
5. 强化学习放在真实历史数据可用之后，用于排序策略推荐，不直接替代可行性约束求解。
