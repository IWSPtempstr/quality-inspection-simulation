# Figma Make 原型交互 Prompt：电器产品质量检测多 Agent 排程业务后台

## 使用方式

将“Figma Make Prompt”一节完整复制到 Figma Make。第一版目标是生成一个多页面中文业务后台原型，用于展示和细化当前项目的订单、排程、执行、事件、Agent 辅助和 Trace 可观测流程。

该原型不应表现为营销站或概念大屏，而应表现为调度员、检测员、管理员和评测人员可以理解的业务系统。

## Figma Make Prompt

```text
请生成一个中文业务后台原型，产品名称为“电器产品质量检测多 Agent 排程系统”。

这是面向电器产品质量监督检验中心的调度管理系统。用户包括调度员、检测员、管理员和评测人员。系统管理普通、加急、VIP 订单，模拟 CCC、CVC、国际认证检测任务，根据设备、人员、检测项目、优先级、SLA、前处理、跨实验室转运和维护窗口生成检测队列与排程。

设计目标：
- 做成真实可用的多页面业务后台，不要营销首页。
- 信息密度高，适合调度员长时间使用。
- 风格克制、专业、现代，避免大面积渐变、装饰性插画和夸张 hero。
- 使用中文界面。
- 页面要体现多 Agent 辅助，但 Agent 不能直接写业务状态。
- 所有写操作必须由用户点击确认按钮触发。
- Agent 输出只能是草稿、推荐、解释、通知文案、任务路由建议。
- LLM 失败时显示 deterministic_fallback 状态，而不是空白错误。

整体布局：
- 左侧固定导航栏，包含：仪表盘、订单、队列与排程、执行看板、事件中心、通知、知识库、Agent 控制台、评测与 Trace、审计日志。
- 顶部栏显示：当前角色、仿真时钟、当前排程批次、待处理事件数、系统健康状态、通知入口。
- 主区域为业务页面。
- 右侧可折叠 Agent 助手面板，在相关页面展示当前 Agent 建议、模式、引用、Trace ID、人工确认按钮。

视觉风格：
- 背景使用浅灰白业务后台色。
- 主色使用稳重蓝绿色或深青色，警告使用橙色，风险使用红色，成功使用绿色。
- 表格、筛选器、甘特图、状态徽标、分段控件、抽屉面板、确认弹窗是主要组件。
- 卡片圆角不要超过 8px。
- 不要使用营销式 hero，不要使用装饰性大图。
- 文本不要溢出，移动端可以压缩为抽屉导航和堆叠布局。

请生成以下页面和关键交互状态：

1. 仪表盘
- 顶部指标：待排订单、运行中订单、VIP SLA 达成率、加急延误率、设备利用率、人员阻塞数、待处理事件数。
- 中部左侧：当前队列摘要，按 VIP / 加急 / 普通分组。
- 中部右侧：设备负载热力表，展示安全检测设备、电磁兼容设备、性能测试台、环境试验箱。
- 下方：事件闭环表，字段为事件、等级、对象、状态、触发时间。
- 右侧 Agent 面板：显示“今日排程风险解释”，包含模式 llm/deterministic_fallback、瓶颈资源、SLA 风险、建议动作。建议动作只能是“查看队列”“打开事件”“生成说明”，不能直接重排。

2. 订单管理
- 顶部筛选：订单类型、状态、认证类型、SLA 风险、到达时间。
- 主表字段：订单号、客户、样品、订单类型、认证类型、检测项目、到达时间、承诺完成时间、状态、SLA、操作。
- 操作包含查看、编辑、复检、取消。
- 新建订单按钮打开右侧抽屉表单。
- 抽屉表单包含客户、样品、订单类型、认证类型、样品数量、到达时间、承诺完成时间、检测项目。
- 表单中有“用自然语言生成草稿”入口，调用 Order Manager Agent。
- Agent 只生成订单草稿，页面必须显示“草稿未创建订单”，用户点击“确认创建订单”后才创建。
- 显示字段校验、缺失字段提示、非法枚举被拦截提示。

3. 项目推荐 / 订单草稿确认
- 作为订单抽屉内的一个步骤式流程。
- 用户输入样品描述和认证目标。
- Project Identifier Agent 返回推荐检测项目和必检项目。
- 推荐结果分为：必检项目、建议项目、可选项目、依据。
- 用户可勾选项目并返回订单草稿。
- 必检项目默认锁定，不允许取消。
- 页面说明“Agent 推荐不会直接创建检测任务”。

4. 队列与排程
- 顶部按钮：查看最新队列、比较策略、触发重排。
- 触发重排按钮必须打开确认弹窗，说明这是确定性调度 API 操作，不是 Agent 自动执行。
- 指标：已排订单、阻塞订单、准时率、平均等待分钟、转运等待分钟、人员阻塞数。
- 策略对比表：priority_fifo、earliest_due_date、shortest_processing_time、bottleneck_resource_first、hybrid_weighted、sla_guarded_hybrid、cp_sat_rolling。
- 字段：策略、评分、已排订单、阻塞订单、VIP 延误、加急延误、平均等待、fallback 原因。
- 默认高亮系统采用策略。
- 下方甘特图按设备分泳道展示步骤，步骤类型包括前处理、准备、检测、转运。
- 点击甘特条打开步骤详情抽屉，显示订单、设备、人员、开始结束时间、锁定状态、SLA 风险。
- 阻塞原因区展示订单、阻塞类型、解释、处理方向。
- Queue Scheduler Agent 只能解释排程，不能直接重排。

5. 执行看板
- 面向检测员。
- 左侧显示“我的待办步骤”：前处理、检测、转运、复核。
- 中间是进行中步骤，展示设备、样品、预计结束时间、人员。
- 操作按钮：开始检测、完成检测、上报异常。
- 点击开始检测后步骤变为 locked，显示“已锁定，自动重排不会打断此步骤”。
- 完成检测后显示完成回写结果和下一步建议。
- 上报异常会创建事件草稿，用户确认后写入事件。

6. 事件中心
- 顶部筛选：事件类型、严重度、状态、对象类型。
- 表格字段：事件、严重度、对象、fingerprint、防抖状态、状态、创建时间、处理人。
- 事件详情抽屉显示 payload、影响订单、相关排程批次、处理记录。
- 操作：标记解决、触发心跳、查看影响排程。
- 高严重度事件展示“可能立即触发 heartbeat”的提示。
- Exception Analyzer Agent 可解释异常原因，但不能直接解决事件。

7. 通知中心
- 通知列表按未读、SLA 风险、设备空闲、检测完成、人员阻塞、复检要求分类。
- 字段：通知类型、目标员工、订单、内容、触发时间、状态。
- Notification Agent 可生成增强文案。
- 页面必须显示“增强文案不会改变通知触发条件”。
- 用户可查看规则原文和 Agent 增强文案对比。

8. 知识库
- 搜索框：输入认证、设备、检测项目相关问题。
- 搜索结果必须显示引用来源。
- RAG Retriever Agent 回答区包含 citations、置信提示、fallback 状态。
- 提供“重建索引”按钮，但需要确认弹窗。

9. Agent 控制台
- 展示 Agent 列表：Orchestrator、Order Manager、Project Identifier、RAG Retriever、Queue Scheduler、Equipment Monitor、Notification Agent、Exception Analyzer。
- 每个 Agent 卡片显示任务类型、权限、是否可写、fallback 状态。
- 安全边界表：
  - draft_order_from_text：只返回草稿，不创建订单。
  - route_user_query：只返回推荐，不执行任务。
  - identify_projects：保留确定性必检规则。
  - explain_schedule / analyze_exception / search_knowledge：只读。
  - generate_notifications：只增强文案，不改变触发条件。
- 提供自然语言输入框，Orchestrator 返回推荐任务和目标 Agent。
- 推荐结果只显示“建议执行”，用户必须点击对应业务按钮进入确定性流程。

10. 评测与 Trace
- 顶部指标：Agent 成功率、轨迹符合率、MCP 成功率、RAG Hit@3、fallback 连续次数、P95 延迟、Token 消耗。
- Trace 列表字段：trace_id、任务类型、visited_agents、handoffs、tool_calls、fallback_used、latency、tokens、状态。
- Trace 详情展示时间线：用户请求、Orchestrator、子 Agent、工具调用、fallback、最终响应。
- 离线评测区可运行评测，展示通过/失败、失败规则、失败样例导出。
- 显示“评价由确定性规则和阈值完成，不依赖 AI 自评”。

11. 审计日志
- 表格展示用户、角色、动作、目标类型、目标 ID、时间、详情。
- 支持筛选 orders、schedule_step、scheduler、agent_task、notification、event。
- 高亮写操作审计，如创建订单、触发重排、步骤完成、事件解决。

关键用户流程：
A. 自然语言录单
用户进入订单页 -> 点击新建订单 -> 输入自然语言需求 -> Agent 生成草稿 -> 显示缺失字段和推荐项目 -> 用户补全 -> 点击确认创建 -> 订单进入队列 -> 自动写入 order_created 事件。

B. 项目识别
用户输入样品描述和认证目标 -> Project Identifier Agent 返回必检和推荐项目 -> 用户确认项目 -> 回填订单草稿 -> 人工确认创建。

C. 队列重排
调度员进入队列与排程 -> 点击比较策略 -> 查看策略评分和 fallback 原因 -> 点击触发重排 -> 确认弹窗 -> 系统通过确定性 API 重排 -> 甘特图和指标更新。

D. 执行回写
检测员进入执行看板 -> 选择待办步骤 -> 点击开始检测 -> 步骤变为 running 和 locked -> 完成后点击完成检测 -> 订单状态和下一步更新 -> 写入审计日志。

E. 异常处理
设备故障或人员阻塞事件出现 -> 事件中心查看详情 -> Exception Analyzer Agent 解释原因和影响 -> 调度员选择触发心跳或标记解决事件 -> 系统更新排程和事件状态。

F. Agent 可观测
用户在 Agent 控制台输入“为什么 VIP 订单延期？” -> Orchestrator 路由到 Queue Scheduler 或 Exception Analyzer -> 返回结构化解释 -> Trace 页面显示 visited_agents、handoffs、tool_calls、fallback_used、tokens。

请生成可点击的多页面原型，页面之间通过导航和关键按钮串联。所有示例数据使用合成数据，不要暗示真实检测中心数据。请优先保证业务后台可读性、表格密度、状态清晰和安全边界可见。
```

## 页面结构

第一版原型包含 10 个主页面，外加订单抽屉中的“项目推荐 / 草稿确认”流程。

| 页面 | 主要目标 | 核心组件 |
| --- | --- | --- |
| 仪表盘 | 查看整体队列、SLA、资源和事件风险 | 指标卡、队列摘要、设备负载、事件表、Agent 风险解释 |
| 订单管理 | 管理订单和录单草稿 | 筛选器、订单表、新建抽屉、自然语言草稿、项目推荐 |
| 队列与排程 | 比较策略并查看排程结果 | 策略表、排程指标、设备甘特图、步骤详情、阻塞解释 |
| 执行看板 | 支持检测员开始/完成步骤 | 待办列表、运行中步骤、锁定提示、异常上报 |
| 事件中心 | 处理排程事件和异常 | 事件表、详情抽屉、解决/心跳操作、异常解释 |
| 通知中心 | 查看通知和增强文案 | 通知分类、规则文案、Agent 增强文案对比 |
| 知识库 | 查询认证和设备知识 | 搜索框、RAG 回答、引用来源、索引状态 |
| Agent 控制台 | 展示 Agent 能力和安全边界 | Agent 卡片、权限矩阵、自然语言路由、建议结果 |
| 评测与 Trace | 观察 Agent 运行质量 | 指标卡、Trace 表、工具调用时间线、离线评测 |
| 审计日志 | 追踪关键写操作 | 审计表、角色/动作筛选、详情抽屉 |

## 用户流程

### 自然语言录单

1. 调度员进入“订单管理”。
2. 点击“新建订单”打开右侧抽屉。
3. 输入自然语言需求，例如“客户送检一批加急电磁兼容样品，希望三天内完成”。
4. Order Manager Agent 生成订单草稿，并标注 `mode`、缺失字段和校验提示。
5. 用户补齐字段，确认检测项目。
6. 用户点击“确认创建订单”。
7. 系统通过确定性订单 API 创建订单，写入 `order_created` 排程事件。

### 项目识别

1. 用户在订单抽屉输入样品描述和认证目标。
2. Project Identifier Agent 返回必检项目、建议项目、可选项目和依据。
3. 必检项目默认锁定，用户只能勾选建议/可选项目。
4. 用户确认后回填订单草稿。
5. 页面显示“项目推荐不会直接创建检测任务”。

### 队列重排

1. 调度员进入“队列与排程”。
2. 点击“比较策略”查看各候选策略评分。
3. 查看 `sla_guarded_hybrid`、`cp_sat_rolling` 等策略的准时率、阻塞数和 fallback 原因。
4. 点击“触发重排”。
5. 确认弹窗说明：这是确定性调度 API 操作，不是 Agent 自动执行。
6. 用户确认后排程刷新，甘特图和步骤表更新。

### 执行回写

1. 检测员进入“执行看板”。
2. 选择待办步骤。
3. 点击“开始检测”，步骤变为 `running` 和 `locked`。
4. 页面提示：自动重排不会打断已锁定步骤。
5. 检测完成后点击“完成检测”。
6. 系统回写步骤完成状态，记录审计日志，并展示下一步。

### 异常闭环

1. 设备故障、人员阻塞或耗材不足事件进入“事件中心”。
2. 调度员打开事件详情，查看影响订单和相关排程批次。
3. Exception Analyzer Agent 生成结构化解释和处理建议。
4. 用户选择“触发心跳”或“标记解决”。
5. 系统更新事件状态和相关排程。

### Agent 可观测

1. 用户在“Agent 控制台”输入只读问题，例如“为什么 VIP 订单延期？”。
2. Orchestrator 返回推荐任务和目标 Agent。
3. Queue Scheduler 或 Exception Analyzer 输出结构化解释。
4. 用户进入“评测与 Trace”查看 `visited_agents`、`handoffs`、`tool_calls`、`fallback_used` 和 token 消耗。

## 安全边界

原型必须持续展示以下边界：

- `draft_order_from_text` 只返回订单草稿，不创建订单。
- `route_user_query` 只返回推荐任务，不执行任务。
- `identify_projects` 必须保留确定性必检项目。
- `search_knowledge`、`explain_schedule`、`analyze_exception` 是只读能力。
- `generate_notifications` 只增强文案，不改变通知触发条件。
- 订单创建、重排、步骤开始/完成、事件解决、索引重建都需要用户确认后调用确定性 API。

## Figma Make 后续迭代建议

生成第一版后，优先检查：

- 页面是否是业务后台，而不是营销页或大屏展示页。
- 左侧导航和顶部状态栏是否贯穿所有页面。
- 订单草稿、项目推荐、排程解释等 Agent 输出是否明确标注“需人工确认”。
- 甘特图、策略对比、Trace 时间线是否足够清晰。
- 所有写操作是否都有确认弹窗或明确按钮。
- 移动端是否保持信息可读，没有文字重叠。
